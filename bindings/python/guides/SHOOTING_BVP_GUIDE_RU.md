# Руководство по ShootingBVP для Python

`ShootingBvpSolver` предоставляет доступ к символьному методу стрельбы из
основного Rust-крейта. Его область применения намеренно ограничена скалярной
задачей второго порядка, записанной как система первого порядка с двумя
состояниями `u = [y, y']`. Это хороший вариант для небольших задач, но не
универсальная замена коллокационным методам: при сложных граничных условиях
стрельба может быть плохо обусловлена, а для больших систем она не рекомендуется.

## Задача и граничные условия

Передайте два выражения правой части в порядке состояний, два имени состояний,
независимую переменную, интервал и по одному условию на каждом конце. Тип
`"dirichlet"` задаёт значение `y`, а `"neumann"` задаёт значение `y'`.
Параметр `initial_guess` задаёт пробное значение свободной компоненты состояния
слева. Внешний итерационный метод стрельбы использует секущие.

```python
import math

from rustedscithe import Expr, ShootingBvpSolver, SolverOptions

solver = ShootingBvpSolver(
    equations=[Expr.parse("v"), Expr.parse("-y")],  # y' = v, v' = -y
    state_variables=["y", "v"],
    independent_variable="x",
    t_start=0.0,
    t_end=math.pi / 2.0,
    left_boundary_type="dirichlet",
    left_boundary_value=0.0,
    right_boundary_type="dirichlet",
    right_boundary_value=1.0,
    initial_guess=0.5,
    tolerance=1e-8,
    max_iterations=100,
    step_size=0.01,
    ivp_method="rk45",
    options=SolverOptions(frontend="atom_native", telemetry="timings"),
)
solution = solver.solve()
print("найденный начальный наклон:", solution.shooting_value)
print("форма траектории:", solution.states_array().shape)
print("телеметрия:", solution.telemetry)
```

Здесь решается `y'' = -y`, `y(0)=0`, `y(pi/2)=1`. Точное решение — `sin(x)`,
а найденный начальный наклон должен быть близок к единице. `states_array()` —
владеющий данными NumPy-массив формы `(число_узлов, 2)` со столбцами `[y, y']`.

## Фронтенд, IVP-солвер и параметры

Символьный маршрут выбирается через `SolverOptions(frontend=...)`:

- `expr_legacy` — фронтенд по умолчанию.
- `atom_native` — фронтенд на основе AtomView.

Исполнение выполняется через Lambdify; AOT этим солвером не поддерживается.
Используется только Dense-путь. `execution_policy` принимает `sequential` или
`parallel`. Параметр `ivp_method` принимает `rk45`, `dopri`, `ab4`,
`radau`, `bdf`, `backward_euler` и `lsode2`. Параметр `solver_parameters`
передаёт словарь настроек выбранного IVP-солвера; допустимы скалярные значения
и прямоугольные матрицы в виде списка списков. Проверку конкретных ключей
выполняет соответствующий нативный IVP-адаптер.

## Телеметрия и логирование

Телеметрия выключена при `SolverOptions(telemetry="off")`. Режим `counters`
собирает число шагов секущих, вычислений граничной невязки и запусков IVP без
таймеров; `timings` измеряет интеграции невязки, финальное интегрирование,
секущую фазу и всё решение без дискретных счётчиков; `detailed` включает оба
канала. `solution.telemetry` содержит только каналы выбранного режима.
`preparation_ms` отдельно показывает wall-clock символьной подготовки.

Логирование Rust независимо от телеметрии и по умолчанию выключено. Для
включения вызовите `options.set_logging_level("info")`; также доступны уровни
`error`, `warn` и `debug`. Создаётся один timestamped-файл на процесс. Папку
можно задать переменной `RST_SOLVER_LOG_DIR` до запуска Python.

## Когда применять

Метод стрельбы интегрирует задачу от одной границы и подбирает свободное
начальное состояние, чтобы выполнить условие на другой границе. Это может быть
эффективно для одного уравнения или очень маленькой системы с устойчивой IVP-
динамикой. Неустойчивые моды и чувствительность к начальным данным могут сделать
его неподходящим для конкретной BVP. Для больших и сложных задач используйте
`BvpDampSolver` или `BvpSciSolver` и сравнивайте солверы на одной и той же задаче.
