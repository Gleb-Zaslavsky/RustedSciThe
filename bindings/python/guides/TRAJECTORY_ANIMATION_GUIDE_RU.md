# Анимация траекторий на Python

Интерактивные функции показывают траекторию, уже возвращённую IVP-солвером.
Они не интегрируют уравнения, не меняют состояние солвера и не вычисляют
символьные callbacks. Это средство исследования и обучения, а не численный
постпроцессор и не замена сохранённым данным решения.

## Контракт входных данных

```python
from rustedscithe import animate_trajectory_2d, animate_trajectory_3d

animate_trajectory_2d(points_xy, times, axis_names=("x", "z"), speed=1.0)
animate_trajectory_3d(points_xyz, times, axis_names=("x", "y", "z"), speed=1.0)
```

`points_xy` имеет форму `(samples, 2)`, `points_xyz` — `(samples, 3)`, а
`times` — `(samples,)`. Python API использует NumPy layout «одна строка на
sample»; binding один раз копирует и транспонирует данные для нативного
представления. Несовпадение формы, пустая траектория, нечисловые координаты или
время, координаты за конечным диапазоном `f32`, немонотонное время и неположи-
тельная либо нечисловая скорость отклоняются до открытия окна. Одна точка
допускается. Время может строго возрастать или строго убывать.

Разность соседних временных меток задаёт интервал воспроизведения, делённый
на `speed`: например, `speed=2` ускоряет его вдвое. Часы сохраняют остаток
времени между границами кадров и повторяют цикл с последним наблюдавшимся
интервалом. Маркер текущей точки обновляется с частотой отрисовки и может
перепрыгивать через близкие adaptive samples; линия при этом включает сегменты
траектории до текущей точки. Интервалы меньше одной
микросекунды ограничиваются снизу для визуализации. Координаты внутри Bevy
хранятся как `f32`, поэтому анимация не предназначена для точного экспорта.
Интервалы больше `1e9` секунд воспроизведения отклоняются, чтобы окно не
выглядело зависшим на практически неприемлемое время.
Размах координат по каждой оси также должен помещаться в конечный диапазон
геометрии `f32`.

## Анимация результата солвера

`examples/lsode2_lorenz_animation.py` решает систему Лоренца и по умолчанию
открывает 3D-траекторию. Выберите другой вид или `--no-animate` для пакетного
запуска без окна:

```console
python examples/lsode2_lorenz_animation.py --no-animate
python examples/lsode2_lorenz_animation.py --animate 2d
python examples/lsode2_lorenz_animation.py --animate 3d --speed 1.5
python examples/lsode2_lorenz_animation.py --animate both
```

Команда без аргументов открывает 3D-проекцию `(x,y,z)`, двумерная использует
`(x,z)`. Режим `both`
сначала открывает 2D-окно, а после его закрытия запускает 3D в новом дочернем
процессе, не решая задачу повторно. Пример трёх тел по умолчанию открывает
анимацию плоской траектории выбранного тела. Для пакетного запуска без окна
используйте `--no-animate`:

```console
python examples/lsode2_three_body_animation.py --no-animate
python examples/lsode2_three_body_animation.py --animate --body 1
```

Координаты анимации равномерно нормализуются только для отображения, чтобы
маленькая или смещённая траектория помещалась в окне. Индикатор позиции при
этом показывает исходные координаты решения.

Для готового IVP-результата есть `animate_solution_2d(solution, columns=(0, 2), ...)`
и `animate_solution_3d(solution, columns=(0, 1, 2), ...)`. Они читают detached
NumPy-массивы состояний и времени, выбирают столбцы и не вызывают повторный
`solve()` или вычисление callbacks.

## Поведение при запуске

Открытие окна Bevy синхронное: вызов блокируется, пока окно не будет закрыто;
нажмите Esc или используйте системную кнопку закрытия. Каждый показ запускает
один native event loop в отдельном короткоживущем Python-процессе. Это
изолирует ограничение winit «один event loop на процесс»: после закрытия 2D
окна можно вызвать 3D-анимацию в той же Python-сессии. Родительский процесс
ждёт завершения окна и возвращает typed ошибки. Вызывать анимацию следует из
главного Python-потока; вызов из worker thread вернёт `RuntimeError` до запуска
процесса. Нужен доступный desktop renderer; интерактивный показ намеренно не
входит в обычные headless-тесты. Импорт `rustedscithe` и решение IVP сами по
себе окна не открывают.
