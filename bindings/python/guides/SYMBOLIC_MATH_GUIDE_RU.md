# Символьная математика в Python

`rustedscithe.Expr` — Python-объект, представляющий выражение во внутреннем
символьном дереве крейта. Разбор, дифференцирование, подстановки, упрощение и
подготовка вычисляемых функций выполняются в Rust. Зависимость от SymPy не
требуется.

## Построение выражений

```python
from rustedscithe import Expr, symbols

x, y = symbols(["x", "y"])
f = x**2 + 3 * x * y + y.sin()
print(f)
print(f.pretty_print())
print(f.variables())  # свободные переменные в сортированном порядке
```

Символы создаются через `Expr.variable`, `Expr.symbols`, `Expr.indexed` или
функции `symbol`, `symbols`, `indexed_symbols`. Арифметические операции
принимают конечные числовые скаляры; `bool` и `NaN/inf` отклоняются.
Выражения неизменяемы: операция преобразования возвращает новый объект.

## Производные и подстановки

```python
df_dx = f.diff("x")
d2f_dx2 = f.diff_n("x", 2)
gradient = f.gradient()  # порядок совпадает с f.variables()

rate = Expr.variable("rate")
model = (rate * x + y).where_substitute(
    {"rate": Expr.constant(2.0)}
)

# Одновременная подстановка нескольких известных числовых значений.
fixed = (x + y).substitute_values({"x": 1.5, "y": -0.25})
```

`substitute_expr` заменяет один символ выражением. `substitute_many` и
`where_substitute` рекурсивно разрешают цепочки определений независимо от
порядка элементов словаря. Циклы и повторные имена считаются ошибками.
Символы, которых нет в словаре, остаются свободными. `rename_variable`
переименовывает переменную в новом выражении, а `contains_variable` проверяет
её наличие.

## Упрощение и области определения

`simplify()` запускает native-упрощение. Это символьное преобразование, а не
система доказательств и не преобразование, сохраняющее область определения.
Например, `(x / x).simplify()` становится `1`, хотя исходное выражение не
определено при `x = 0`. Структурное равенство, алгебраическая эквивалентность
при заданных предположениях и совпадение в нескольких численных точках —
разные утверждения. Преобразования с логарифмами, степенями и частными могут
иметь ограничения области определения. Если сингулярности важны для модели,
сохраняйте исходное выражение или отдельно проверяйте область. Численные
проверки полезны как регрессионные тесты, но не доказывают эквивалентность на
всей области.

`taylor_series(variable, center, order)` строит формальный полином Тейлора;
остальные свободные символы остаются в выражении. Метод не проверяет сходимость
ряда и радиус сходимости. Для ограничения роста дерева порядок ограничен 32.

## Интегрирование

`integrate(variable)` просит native-интегратор найти неопределённую первообразную
для поддерживаемого подмножества элементарных выражений. Если форма не
поддерживается, возникает `UnsupportedSymbolicOperationError` с полями
`stage == "symbolic_integration"` и `operation == "integrate"`. Константа
интегрирования не добавляется.

Текущее правило ядра преобразует `1/x` в `ln(x)`. Оно не задаёт глобальную
вещественную первообразную на отрицательной полуоси и через сингулярность в
нуле. Пользователь должен сам определить и соблюдать подходящую область.
Определённый интеграл пока не входит в этот Python API; подстановка значений
на концах сама по себе не доказывает сходимость.

Для явно численного интегрирования на конечном интервале используйте
`Expr.integrate_simpson(lower, upper, subdivisions)`. Допускается не более
одной свободной переменной, границы должны быть конечными, а число разбиений
положительным и чётным. Результат проверяется на конечность, но это не
доказывает отсутствие внутренних особенностей или сходимость квадратуры.
Конечные границы в обратном порядке дают интеграл с обратным знаком.
Для невзвешенного интеграла на конечном интервале также доступен
`Expr.integrate_gauss_legendre(lower, upper, degree)`: степень должна быть
в диапазоне 1..4096, а требования к одномерности и конечности результата такие
же. Ни одно из этих правил не обнаруживает внутренние особенности и не
сертифицирует сходимость.

Взвешенные правила для всей прямой и полуоси имеют отдельные имена; их вес
входит в вычисляемый интеграл: `integrate_gauss_hermite(degree)` считает
`integral(exp(-x**2) * f(x), x=-inf..inf)`, а
`integrate_gauss_laguerre(degree, alpha=0.5)` считает
`integral(x**alpha * exp(-x) * f(x), x=0..inf)` при конечном `alpha > -1`.
Для обоих методов степень ограничена диапазоном 1..4096. Это взвешенные
интегралы, а не автоматическое преобразование произвольного несобственного
интеграла без веса.

## Символьные векторы и матрицы

`ExprVector([...])` и `ExprMatrix([[...], ...])` содержат неизменяемые
коллекции `Expr`. Строки матрицы должны иметь одинаковую длину. Оба типа
возвращают сортированный список `variables()` и используют ровно этот порядок
при вычислении:

```python
import numpy as np
from rustedscithe import Expr, ExprMatrix, ExprVector

x, y = Expr.symbols(["x", "y"])
v = ExprVector([x + y, x * y])
A = ExprMatrix([[x, y], [x * y, x**2]])

v_values = v.evaluate([2.0, 3.0])  # NumPy, shape (2,)
A_values = A.evaluate([2.0, 3.0])  # NumPy, shape (2, 2), порядок строк
assert isinstance(A_values, np.ndarray)
At = A.transpose()
Av = A.matvec(v)
det_A = A.determinant()  # native determinant поддерживает размеры 1..3
B = ExprMatrix([[Expr.constant(1.0), y], [x, Expr.constant(2.0)]])
AB = A.matmul(B)         # обычное умножение строк на столбцы
A_entrywise_B = A.hadamard(B)  # поэлементное умножение
```

Векторы поддерживают индексацию, производные, подстановку, упрощение и
скалярное произведение. Матрицы поддерживают форму и индексацию, строки и
столбцы, транспонирование, производные, подстановку, упрощение, произведение
матрицы на вектор, обычное матричное произведение `matmul`, явное поэлементное
произведение `hadamard`, след и определитель до 3x3. Разные имена методов
исключают неоднозначность оператора `*`. Некорректные индексы, ragged-строки
и несовместимые размеры произведений отклоняются до native assertions;
пустые результирующие формы сохраняются. Расширенные block-, inverse- и
Kronecker-операции пока не входят в Python-контракт.

## Подготовленные скалярные функции

`Expr.lambdify()` один раз подготавливает повторно используемую функцию.
По умолчанию используется `SymbolicFrontend.ExprLegacy`; `AtomNative` выбирает
однократное преобразование в упакованное Atom-представление. Далее оба пути
вычисляют в Rust. `evaluate_batch()` принимает NumPy-массив формы
`(samples, variables)` и возвращает собственный массив формы `(samples,)`.

Телеметрия выключена по умолчанию. При `lambdify(diagnostics=True)` записываются
время подготовки, число callback-вызовов и время callback. Когда измерение
выключено, время подготовки равно `None`, а не нулю. Callback-таймер не
включает преобразование Python/NumPy и служит для разбора затрат, а не заменяет
контролируемый benchmark.

Запускаемые примеры: [`symbolic_calculus.py`](../examples/symbolic_calculus.py)
и [`symbolic_arrays.py`](../examples/symbolic_arrays.py).

## Подготовленные системы невязок

`SymbolicSystem.lambdify()` подготавливает всю систему невязок и якобиан через
production symbolic backend нелинейного ядра. `ExprLegacy` и `AtomNative` —
раздельные нативные маршруты; AtomNative не дифференцирует выражения сначала
через Expr. Подготовленный объект повторно использует Rust-буферы входа,
невязок и плотного якобиана. NumPy batch-вход имеет форму
`(samples, variables)`, невязки — `(samples, residuals)`, а плотные якобианы —
`(samples, residuals, variables)`. Поддерживаются strided views.

Методы `*_into` заполняют и возвращают принадлежащие приложению массивы.
Требуются точные формы и `float64`; read-only или уже занятый буфер отклоняется.
Весь batch вычисляется до записи в `out`, поэтому входной массив можно
переиспользовать и как выходной. Native batch-workspace сохраняет ёмкость до
наибольшего запрошенного batch. Плотный якобиан создаётся только по явному
запросу: его объём растёт как `samples * residuals * variables`.

```python
x, y = Expr.symbols(["x", "y"])
system = SymbolicSystem([x**2 + y, x * y], ["x", "y"])
prepared = system.lambdify(frontend=SymbolicFrontend.AtomNative)
points = np.array([[2.0, 3.0], [4.0, 5.0]])
residuals = prepared.evaluate_batch(points)            # (2, 2)
jacobians = prepared.evaluate_jacobian_batch(points)  # (2, 2, 2)
prepared.evaluate_batch_into(points, residuals)        # заполняет и возвращает residuals
```

При `diagnostics=True` счётчик `evaluations` считает scalar-equivalent элементы
невязки и якобиана, а `callback_time_ms` — время нативного вычисления системы.
`preparation_stages` содержит включённые stage-тайминги ядра; неприменимые
стадии остаются `None`. При отключённой диагностике timeline равен `None`.
Python/NumPy-преобразования не входят ни в evaluation, ни в preparation-таймеры.

Полный запускаемый пример пакетной работы с системой:
[`symbolic_system_numpy_batch.py`](../examples/symbolic_system_numpy_batch.py).
Wrapper-only измерительный скрипт:
[`python_boundary_symbolic_system.py`](../benchmarks/python_boundary_symbolic_system.py);
он не подменяет измерения Rust-core.
