# Faithful banded-линейная алгебра

`rustedscithe` предоставляет стабильный LAPACK-подобный путь banded LU из
`somelinalg` через `BandedMatrix` и `LapackStyleBandedLuFaithful`. Этот API
предназначен для задач, где ширина ленты известна заранее. Матрица хранится
в компактном виде и при обычной факторизации или решении не превращается в
плотную матрицу `n x n` NumPy.

## Компактное хранение

Для матрицы размера `n` с `kl` нижними и `ku` верхними диагоналями форма
входа равна `(kl + ku + 1, n)`. Совместимое с native-реализацией правило:

```text
ab[ku + i - j, j] = A[i, j]
```

Для tridiagonal-случая (`kl=ku=1`) строки идут так: верхняя диагональ,
главная диагональ, нижняя диагональ. Массив копируется при создании, поэтому
последующее изменение исходного NumPy-массива не меняет `BandedMatrix`.

```python
import numpy as np
from rustedscithe import BandedMatrix

compact = np.asarray(
    [
        [0.0, 1.0, 1.0, 1.0],  # верхняя диагональ; первый слот -- padding края
        [4.0, 4.0, 4.0, 4.0],  # главная диагональ
        [2.0, 2.0, 2.0, 0.0],  # нижняя диагональ
    ],
    dtype=np.float64,
)
matrix = BandedMatrix(4, kl=1, ku=1, values=compact)
```

Конструктор `from_bands` удобен, если диагонали уже хранятся отдельно.
`diagonal` имеет форму `(n)`, а `lower` и `upper`, если переданы, формы
`(kl, n)` и `(ku, n)`. Строки идут от ближайшей к главной диагонали к
внешней. Краевые элементы, которые выходят за границы матрицы, игнорируются,
как в компактном LAPACK-хранении.

Все массивы имеют тип `float64`, проверяются на конечность, размерность и
форму до входа в native-код. Неверные размеры, `NaN`/`inf` и недопустимые
ширины дают `InvalidConfigurationError`, а не молча меняют форму или создают
плотную матрицу.

## Одна факторизация и много решений

`LapackStyleBandedLuFaithful` владеет факторизацией и переиспользуется для
нескольких правых частей. После `factor()` факторизация независима от
исходной матрицы. `solve()` принимает вектор формы `(n)`, а
`solve_multiple()` матрицу `(n, nrhs)` и возвращает ту же форму.
`solve_in_place()` доступен для contiguous writable-вектора, когда важна
экономия отдельной аллокации результата.

```python
from rustedscithe import LapackStyleBandedLuFaithful

lu = LapackStyleBandedLuFaithful(n=4, kl=1, ku=1)
lu.factor(matrix)
x = lu.solve(np.asarray([6.0, 13.0, 20.0, 22.0]))
# x == [1.0, 2.0, 3.0, 4.0]
```

Для диагностики доступны `is_factorized`, `ipiv`, `n`, `kl`, `ku`, `kv` и
`ldab`. Метод `factor_residual_relative(matrix)` проверяет факторизацию по
исходному banded-оператору, не меняя обычный путь решения.

## Итерационное уточнение

Уточнение включается явно и не меняет скрытно политику решателя:

```python
report = lu.solve_with_refinement(
    matrix,
    np.asarray([6.0, 13.0, 20.0, 22.0]),
    max_iters=2,
    tolerance=1e-12,
)
print(report.solution_array())
print(report.iterations, report.residual_inf, report.converged)
```

`BandedRefinementResult` владеет отдельным массивом решения и сообщает
абсолютную и относительную невязки в бесконечной норме. Внутренние mutable
буферы Rust наружу не выдаются.

## Ошибки и границы API

Обертка сохраняет различия между ошибками конфигурации, отсутствующей
факторизацией, неверной разметкой RHS, сингулярными/нулевыми pivot-ами и
нечисловым результатом через стабильную иерархию Python exceptions. В
контексте ошибки сохраняются stage `lapack_banded` и операция.

Это API линейной алгебры, а не замена BVP-солверу. У него нет отдельного
логгинга или телеметрии; если он используется внутри BVP/IVP, измерения нужно
брать из native-телеметрии внешнего солвера. API намеренно не принимает
плотный fallback и не обещает преимущество на каждой задаче. Его следует
выбирать, когда структура и ширина матрицы оправдывают компактное хранение.

Рабочий пример находится в
[`somelinalg_banded.py`](../examples/somelinalg_banded.py). Его времена только
иллюстративны; доказательства производительности находятся в отдельных
Rust-core и Python-boundary benchmark reports.
